# homebrew-tap contributor context

`frostyard/homebrew-tap` is a Homebrew tap for Frostyard's Linux applications.
It holds casks that install a binary release of an application, and it
publishes a Homebrew tarball that the Snow Linux images install. The tap is
forked from [`ublue-os/homebrew-tap`](https://github.com/ublue-os/homebrew-tap).
Start at [docs/README.md](docs/README.md).

`AGENTS.md` is the canonical instruction file. `CLAUDE.md`, `GEMINI.md`,
`.cursorrules` and [`.github/copilot-instructions.md`](.github/copilot-instructions.md)
are relative symlinks to it (core ADR-0018, core ADR-0029). Edit only this
file.

## Layout

| Path | What it is |
| --- | --- |

| [`.github/workflows/bump.yml`](.github/workflows/bump.yml) | Daily run of `bump_casks.py`; it opens 1 pull request per stale cask or formula and never pushes to the base branch. |
| [`.github/workflows/publish.yml`](.github/workflows/publish.yml) | `brew pr-pull` for a pull request that carries the label `pr-pull`. |
| [`.github/workflows/tests.yml`](.github/workflows/tests.yml) | `brew test-bot` on a push to `main` and on every pull request. |
| [`.github/workflows/brew-tarball.yml`](.github/workflows/brew-tarball.yml) | Builds a Homebrew tarball for Linux and uploads it to a GitHub release, each Tuesday. |
| [`.github/workflows/ci.yml`](.github/workflows/ci.yml) | Runs `make ci` on every pull request. |
| [`.github/workflows/risk-paths.yml`](.github/workflows/risk-paths.yml) | The caller of core's `pr-triage.yml` workflow: it adds the level label and `risk:high`. |
| [`.github/scripts/bump_casks.py`](.github/scripts/bump_casks.py) | The bump script: version, sha256, verification, branch and pull request. |
| [`.github/scripts/test_*.py`](.github/scripts/) | The unit tests of the bump script, the workflows and the baseline. |
| [`docs/`](docs/README.md) | The documentation index: the design of the tap. |
| [`Makefile`](Makefile) | The gate targets. |
| [`mise.toml`](mise.toml), [`mise.lock`](mise.lock) | The pinned tools. |

## Who writes each path

- **`Casks/nsl.rb` comes from `frostyard/nsl`.** On each stable release,
  GoReleaser in that repository commits the file to a `bump/nsl-<version>`
  branch and opens 1 pull request into `main`, titled
  `fix(cask): bump nsl to v<version>`
  ([nsl ADR-0020](https://github.com/frostyard/nsl/blob/main/docs/adr/0020-homebrew-tap-publication.md)).
  A person reviews and merges it like a `bump.yml` pull request. The file's
  first line says `This file was generated by GoReleaser`. Never edit this
  file by hand: the next release overwrites it. Change `nsl`'s release
  configuration instead. GoReleaser logs a refused pull request (HTTP 422)
  only as a warning, so after an `nsl` release, check that its pull request
  is open here.
- **`bump.yml` writes every other `Casks/*.rb` and `Formula/*.rb`.** The
  scheduled run of `.github/scripts/bump_casks.py` pushes a
  `bump/<item>-<version>` branch and opens 1 pull request into `main`; it
  skips a file that carries the GoReleaser marker, and it never commits to
  `main` itself. A person reviews and merges that pull request.
- **`bump_casks.py` must stay able to bump both kinds.** It reads
  `Casks/*.rb` and `Formula/*.rb`, so keep that layout and keep the file name
  the branch token comes from.

## Workflow rules

- **Every `uses:` is a 40-character commit SHA with a version comment**, such
  as `# v7.0.1`, and a core reusable workflow names the core commit
  (core ADR-0021).
- **Every workflow has top-level `permissions: {}`**, and a job grants only
  the scopes it needs.
- **Every checkout sets `persist-credentials: false`**, and a later step uses
  `gh` with a token from `env` when it needs the API.
- **Every workflow has the top-level `defaults:` block with
  `run:` and `shell: bash`**, with the comment above it that says why: an
  explicit bash runs each step with `-eo pipefail`. `.github/scripts/test_workflows.py`
  fails without it.

## Gate

`make ci` is the gate; it runs `make verify`, which runs `make test`:
`python3 -m unittest discover -s .github/scripts -p 'test_*.py' -v`. The tests
use the Python standard library only. `mise.toml` and `mise.lock` pin Python
3.12 (core ADR-0043); run `mise install` first. CI runs `make ci` in
[`.github/workflows/ci.yml`](.github/workflows/ci.yml).

## Pull requests

- `brew test-bot` in [`.github/workflows/tests.yml`](.github/workflows/tests.yml)
  runs `--only-tap-syntax` on the tap and `--only-formulae` on a pull
  request. It does not install a cask: a cask installs an existing binary
  release.
- A pull request that is ready to merge gets the label `pr-pull`. That label
  starts [`.github/workflows/publish.yml`](.github/workflows/publish.yml),
  which runs `brew pr-pull` on the pull request, pushes the result to `main`
  and deletes the branch. A pull request with no `pr-pull` label is merged as
  it is.
- A pull request that touches a path in
  [`.github/risk-paths.json`](.github/risk-paths.json) gets 1 level label,
  `level:L1` to `level:L4`; L1 and L2 also get `risk:high` (core ADR-0068,
  ADR-0078). The owner reads each level as the risk-paths spec says: L1 is
  every line, L2 the whole diff, L3 a skim of the diff, L4 the title and CI.
  The org floors can raise that level, the workflow never lowers a label that
  the pull request already has, a missing level label only warns, and a missing
  `risk:high` label fails the job. The workflow removes `ready-for-human` when
  the head moves after the label, or when CI at the head is not green (core
  ADR-0077). Its body names each matched path and why the change is safe.
- **A blocking review point adds a guard:** a test that fails without the fix,
  or a rule here when no test can catch it, plus 1 line in
  [`.memory/corrections.jsonl`](.memory/corrections.jsonl)
  ([`.memory/README.md`](.memory/README.md)).
- **A change to a cask comes from its source repository.** A release in the
  application's repository is the source of the version and the sha256; this
  repository gets them from `bump_casks.py` or from GoReleaser, not from a
  hand-written edit.
- **PR text speaks for the repository.** A title, a body, a comment and a
  commit message give the reason in this repository's terms and link the ADR,
  the spec or the issue that applies.
